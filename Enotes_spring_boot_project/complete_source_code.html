  <h2>Project Topic</h2>
  <p>Web-based secure note management system for authenticated users.</p>

  <h2>Abstract</h2>
  <p>This project presents the design and development of a web-based application for secure personal note management. In academic and professional environments, users frequently depend on handwritten notebooks, unsecured text files, or scattered digital documents for storing important information. These approaches often create problems such as poor organization, difficulty in retrieval, risk of unauthorized access, and possible loss of data. To address these issues, the project develops a centralized e-notes platform that allows registered users to create, view, edit, and delete notes through a secure browser-based interface.</p>
  <p>The system is implemented using Java 17 and Spring Boot 3 with supporting technologies including Spring MVC, Spring Security, Spring Data JPA, Hibernate, Thymeleaf, Bootstrap, and MySQL. The application provides user registration, login authentication, password encryption using BCrypt, and role-based access to user-specific resources. A notable feature of the system is its account-protection mechanism. If a user enters incorrect credentials multiple times, the account is temporarily locked for a fixed duration. This helps reduce unauthorized login attempts and improves system trustworthiness.</p>
  <p>The backend architecture follows a layered approach consisting of controller, service, repository, entity, and configuration classes. User data and note data are stored in relational database tables and mapped through JPA entities. Each note is linked to a specific user, ensuring that only the owner can access or modify it. The front end is built using Thymeleaf templates integrated with Bootstrap to provide a clean and responsive user interface.</p>
  <p>From a research and application perspective, the project demonstrates how secure note management can be achieved through modern Java-based web technologies. The study focuses on the practical implementation of authenticated note storage and retrieval rather than large-scale enterprise deployment. The resulting application shows that a lightweight, role-based web system can offer improved usability, security, and data organization compared with conventional note-handling methods.</p>
  <p>The project is relevant to business and technology because it reflects real-world requirements of secure information management, user authentication, and database-driven web application development. It also helps develop conceptual, analytical, and implementation skills in software engineering, security integration, user interface design, and backend data management.</p>

  <h2>Introduction</h2>
  <p>Digital transformation has changed the way information is created, stored, and accessed. Notes, reminders, and small textual records are important forms of information in both education and industry. Students use notes to maintain lecture points, assignments, and references. Professionals use notes for tasks, observations, process records, and short documentation. Even though digital systems are widely available, many users still rely on fragmented or insecure methods to manage their notes.</p>
  <p>An effective note management system should allow easy creation and retrieval of information while also protecting sensitive data from unauthorized access. Security becomes especially important when note data includes personal, academic, or work-related content. Many basic note systems focus on usability but overlook account protection and user-based data segregation. This project is therefore centered on the development of a secure and user-oriented e-notes platform.</p>
  <p>The application created in this project uses Spring Boot to simplify backend development and Spring Security to enforce authenticated access. Each user is allowed to manage only their own notes. Passwords are not stored in plain text but are encrypted using BCrypt. To improve protection further, failed login attempts are tracked and repeated failures lead to temporary account locking. This feature reflects practical security practices used in modern web applications.</p>

  <h2>Need for the Study</h2>
  <ol>
    <li>Physical notebooks can be lost, damaged, or misplaced.</li>
    <li>Unsecured digital files provide weak protection against unauthorized access.</li>
    <li>Scattered note storage makes retrieval and updating inefficient.</li>
    <li>Manual management does not support structured user authentication.</li>
    <li>Existing simple note applications may not demonstrate core software engineering concepts required for academic learning.</li>
  </ol>
  <p>The proposed system addresses these issues by offering secured login, user-linked note storage, and a centralized interface for note operations.</p>

  <h2>Research Problem</h2>
  <p>How can a secure, simple, and user-specific web-based note management system be designed and implemented using Spring Boot and MySQL to improve note organization and access control?</p>

  <h2>Aim</h2>
  <p>To develop a secure e-notes web application that enables authenticated users to manage personal notes efficiently.</p>

  <h2>Objectives</h2>
  <ol>
    <li>To create a registration system for new users.</li>
    <li>To implement secure authentication using Spring Security.</li>
    <li>To encrypt user passwords using BCrypt.</li>
    <li>To develop note creation, viewing, updating, and deletion functions.</li>
    <li>To maintain note ownership by mapping notes to registered users.</li>
    <li>To implement account locking after multiple failed login attempts.</li>
    <li>To store application data using JPA and MySQL.</li>
    <li>To build an easy-to-use interface with Thymeleaf and Bootstrap.</li>
  </ol>

  <h2>Scope of the Study</h2>
  <p>The scope of this project is limited to the design, development, and functional analysis of a secure personal note management application. The system supports user registration, login, user-specific note creation, note viewing, note editing, note deletion, and temporary account locking after repeated failed login attempts. The project is intended as a browser-based academic application built with modern Java web technologies.</p>
  <p>The study does not include advanced collaboration features such as note sharing, attachments, category tagging, reminders, mobile application support, or an administrative dashboard. It also does not attempt enterprise-scale deployment or performance benchmarking. These boundaries help keep the project focused, realistic, and aligned with the current implementation.</p>

  <h2>Hypotheses</h2>
  <p><strong>Null Hypothesis (H0):</strong> The implementation of a secure web-based e-notes system does not significantly improve note management efficiency and access control compared with conventional note handling methods.</p>
  <p><strong>Alternative Hypothesis (H1):</strong> The implementation of a secure web-based e-notes system significantly improves note management efficiency and access control compared with conventional note handling methods.</p>

  <h2>Literature Review</h2>
  <p>The present project is grounded in the broader field of web application development, database systems, and information security. Previous academic and industry work in this area generally highlights three core ideas: centralized information management, secure user authentication, and persistent data storage.</p>
  <p>Studies on information systems emphasize that digital record management improves accessibility, consistency, and retrieval speed. When information is stored in a structured database rather than in isolated files or physical records, users can access it more reliably and maintain it more efficiently. This idea supports the use of relational databases in note management applications.</p>
  <p>Research in software engineering also shows that layered architectures improve maintainability and scalability. In this project, the controller-service-repository structure reflects that principle by separating presentation logic, business logic, and persistence logic. Such modular organization helps future enhancement and testing.</p>
  <p>Literature on authentication and access control consistently recommends secure password handling and restricted access to user-owned resources. BCrypt hashing is widely used because it provides stronger password protection than plain text or weak encoding methods. Similarly, role-based access and login attempt monitoring are accepted practices for reducing unauthorized access.</p>
  <p>Modern web development studies further encourage frameworks that reduce configuration overhead and accelerate enterprise-ready application development. Spring Boot is frequently adopted in academic and professional settings because it supports rapid development, dependency management, and integration with MVC, security, and JPA modules. Thymeleaf is also recognized as a practical server-side templating engine for Java applications that require dynamic page rendering.</p>
  <p>Another important theme in the literature is the role of usability in information systems. A system may be technically secure, but if it is difficult to use, users may avoid it or use insecure alternatives. For this reason, simple interfaces and predictable workflows are often treated as part of successful system design. In the present project, the use of Bootstrap and Thymeleaf helps provide a straightforward user journey from registration to login and then to note management.</p>

  <h2>Research Methodology</h2>
  <h3>Research Design</h3>
  <p>The study adopts a descriptive and exploratory design. It is descriptive because it explains the design and behavior of the developed application. It is exploratory because it investigates how a secure note-management solution can be implemented using Spring Boot technologies.</p>
  <h3>Sampling Technique</h3>
  <p>The project primarily follows a non-probability sampling approach, specifically convenience-based functional validation, where representative use cases such as user registration, login, note creation, note editing, note retrieval, and deletion are considered for evaluation.</p>
  <h3>Data Collection</h3>
  <p>The study uses both primary and secondary sources. Primary sources include functional behavior observed from developing and testing the application modules and input-output validation of registration, authentication, and CRUD operations. Secondary sources include Spring Boot documentation, Spring Security concepts, database design references, and general literature on information systems and secure web applications.</p>
  <h3>Data Preparation</h3>
  <p>The project data is prepared by classifying the system into modules and recording expected and observed outcomes for key operations such as registration, login, failed login handling, note insertion, note retrieval, note modification, and note deletion.</p>
  <h3>Data Analysis</h3>
  <p>The analysis is based on module-wise functional verification and comparison between intended system behavior and observed output. Security features such as password encryption and account lock behavior are also considered during evaluation.</p>

  <h2>System Analysis and Design Summary</h2>
  <ol>
    <li><strong>Entity layer:</strong> Contains User and Notes entities.</li>
    <li><strong>Repository layer:</strong> Provides data access through UserRepository and NotesRepository.</li>
    <li><strong>Service layer:</strong> Handles business logic such as user registration, password encoding, failed-attempt tracking, and account unlocking.</li>
    <li><strong>Controller layer:</strong> Manages HTTP requests for registration, login, and note operations.</li>
    <li><strong>Configuration layer:</strong> Defines password encoding, custom authentication handlers, custom user details, and security rules.</li>
    <li><strong>Presentation layer:</strong> Uses Thymeleaf templates for home, registration, login, add note, view note, and edit note screens.</li>
  </ol>

  <h2>Features Implemented in the Current Project</h2>
  <ol>
    <li>User registration with email uniqueness checking</li>
    <li>Password encryption with BCrypt</li>
    <li>Login using Spring Security</li>
    <li>User role assignment as ROLE_USER</li>
    <li>Temporary account locking after three failed login attempts</li>
    <li>Automatic unlock after lock duration expires</li>
    <li>Add note feature</li>
    <li>View note list for logged-in user</li>
    <li>Edit own note feature</li>
    <li>Delete own note feature</li>
    <li>CSRF token inclusion in forms</li>
    <li>User-specific data access</li>
  </ol>

  <h2>Results</h2>
  <p>The developed system successfully demonstrates the core behavior expected from a secure note management application. The registration module supports user enrollment and prevents duplicate email registration. The authentication module secures application access through Spring Security and encrypted password storage. The note management module enables a logged-in user to add, view, edit, and delete notes. Since notes are mapped to individual users, unauthorized cross-user modification is reduced at the application level.</p>
  <p>The project also includes a basic defensive security mechanism in the form of failed login tracking. After repeated invalid login attempts, the user account is temporarily locked. This helps show practical application of security logic beyond basic username-password verification.</p>
  <p>The results are both theoretical and empirical. Theoretical results are reflected in the successful application of concepts such as layered architecture, authentication, authorization, and object-relational mapping. Empirical results are reflected in the observed functional behavior of the application during module execution.</p>

The project verifies that user authentication, note ownership, and database persistence can be combined into a coherent application. It also highlights the value of integrating security at the design stage rather than treating it as an optional add-on.</p>
  <p>The study also reveals that environment configuration remains an important part of deployment. The project depends on database environment variables for successful runtime operation. This shows that modern application development requires both coding skills and deployment awareness.</p>

package com.becoder.config;

import java.io.IOException;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.security.authentication.LockedException;
import org.springframework.security.core.AuthenticationException;
import org.springframework.security.web.authentication.SimpleUrlAuthenticationFailureHandler;
import org.springframework.stereotype.Component;

import com.becoder.entity.User;
import com.becoder.repository.UserRepository;
import com.becoder.service.UserServiceImpl;

import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

@Component
public class CustomAuthenticationFailureHandler extends SimpleUrlAuthenticationFailureHandler {

	@Autowired
	private UserRepository userRepo;

	@Autowired
	private UserServiceImpl userService;

	public CustomAuthenticationFailureHandler() {
		setDefaultFailureUrl("/signin?error");
	}

	@Override
	public void onAuthenticationFailure(HttpServletRequest request, HttpServletResponse response,
			AuthenticationException exception) throws IOException, ServletException {

		String username = request.getParameter("username");
		User user = userRepo.findByEmail(username);

		if (user != null) {
			if (!user.isAccountNonLocked()) {
				if (userService.unlockAccountIfTimeExpired(user)) {
					exception = new LockedException("Your account has been unlocked. Please try logging in again.");
				} else {
					exception = new LockedException("Your account is locked for 15 minutes due to failed login attempts.");
				}
			} else {
				userService.increaseFailedAttempt(user);
				if (user.getFailedAttempt() >= userService.getMaxFailedAttempts()) {
					userService.lockUser(user);
					exception = new LockedException("Your account is locked for 15 minutes due to 3 failed login attempts.");
				}
			}
		}

		super.onAuthenticationFailure(request, response, exception);
	}
}

package com.becoder.service;

import java.time.LocalDateTime;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.stereotype.Service;
import org.springframework.web.context.request.RequestContextHolder;
import org.springframework.web.context.request.ServletRequestAttributes;

import com.becoder.entity.User;
import com.becoder.repository.UserRepository;

import jakarta.servlet.http.HttpSession;

@Service
public class UserServiceImpl implements UserService {

	private static final int MAX_FAILED_ATTEMPTS = 3;

	private static final long LOCK_DURATION_MINUTES = 15;

	@Autowired
	private UserRepository userRepo;

	@Autowired
	private BCryptPasswordEncoder passwordEncoder;

	@Override
	public User saveUser(User user) {
		user.setRole("ROLE_USER");
		user.setPassword(passwordEncoder.encode(user.getPassword()));
		user.setFailedAttempt(0);
		user.setAccountNonLocked(true);
		user.setLockTime(null);
		User newUser = userRepo.save(user);
		return newUser;
	}

	@Override
	public boolean existEmailCheck(String email) {
		return userRepo.existsByEmail(email);
	}

	@Override
	public void increaseFailedAttempt(User user) {
		user.setFailedAttempt(user.getFailedAttempt() + 1);
		userRepo.save(user);
	}

	@Override
	public void resetFailedAttempts(String email) {
		User user = userRepo.findByEmail(email);
		if (user != null && user.getFailedAttempt() > 0) {
			user.setFailedAttempt(0);
			user.setLockTime(null);
			userRepo.save(user);
		}
	}

	@Override
	public void lockUser(User user) {
		user.setAccountNonLocked(false);
		user.setLockTime(LocalDateTime.now());
		userRepo.save(user);
	}

	@Override
	public boolean unlockAccountIfTimeExpired(User user) {
		if (user.getLockTime() == null) {
			return false;
		}

		LocalDateTime unlockTime = user.getLockTime().plusMinutes(LOCK_DURATION_MINUTES);
		if (LocalDateTime.now().isAfter(unlockTime)) {
			user.setAccountNonLocked(true);
			user.setFailedAttempt(0);
			user.setLockTime(null);
			userRepo.save(user);
			return true;
		}
		return false;
	}

	public void removeSessionMessage() {
		HttpSession session = ((ServletRequestAttributes) (RequestContextHolder.getRequestAttributes())).getRequest()
				.getSession();

		session.removeAttribute("msg");
	}

	public int getMaxFailedAttempts() {
		return MAX_FAILED_ATTEMPTS;
	}

}
