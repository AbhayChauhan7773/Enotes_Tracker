Secure E-Notes Management System Using Spring Boot

Project Report

Project Topic

Web-based secure note management system for authenticated users.

Abstract

This project presents the design and development of a web-based application for secure personal note management. In academic and professional environments, users frequently depend on handwritten notebooks, unsecured text files, or scattered digital documents for storing important information. These approaches often create problems such as poor organization, difficulty in retrieval, risk of unauthorized access, and possible loss of data. To address these issues, the project develops a centralized e-notes platform that allows registered users to create, view, edit, and delete notes through a secure browser-based interface.

The system is implemented using Java 17 and Spring Boot 3 with supporting technologies including Spring MVC, Spring Security, Spring Data JPA, Hibernate, Thymeleaf, Bootstrap, and MySQL. The application provides user registration, login authentication, password encryption using BCrypt, and role-based access to user-specific resources. A notable feature of the system is its account-protection mechanism. If a user enters incorrect credentials multiple times, the account is temporarily locked for a fixed duration. This helps reduce unauthorized login attempts and improves system trustworthiness.

The backend architecture follows a layered approach consisting of controller, service, repository, entity, and configuration classes. User data and note data are stored in relational database tables and mapped through JPA entities. Each note is linked to a specific user, ensuring that only the owner can access or modify it. The front end is built using Thymeleaf templates integrated with Bootstrap to provide a clean and responsive user interface.

From a research and application perspective, the project demonstrates how secure note management can be achieved through modern Java-based web technologies. The study focuses on the practical implementation of authenticated note storage and retrieval rather than large-scale enterprise deployment. The resulting application shows that a lightweight, role-based web system can offer improved usability, security, and data organization compared with conventional note-handling methods.

The project is relevant to business and technology because it reflects real-world requirements of secure information management, user authentication, and database-driven web application development. It also helps develop conceptual, analytical, and implementation skills in software engineering, security integration, user interface design, and backend data management.

Introduction

Digital transformation has changed the way information is created, stored, and accessed. Notes, reminders, and small textual records are important forms of information in both education and industry. Students use notes to maintain lecture points, assignments, and references. Professionals use notes for tasks, observations, process records, and short documentation. Even though digital systems are widely available, many users still rely on fragmented or insecure methods to manage their notes.

An effective note management system should allow easy creation and retrieval of information while also protecting sensitive data from unauthorized access. Security becomes especially important when note data includes personal, academic, or work-related content. Many basic note systems focus on usability but overlook account protection and user-based data segregation. This project is therefore centered on the development of a secure and user-oriented e-notes platform.

The application created in this project uses Spring Boot to simplify backend development and Spring Security to enforce authenticated access. Each user is allowed to manage only their own notes. Passwords are not stored in plain text but are encrypted using BCrypt. To improve protection further, failed login attempts are tracked and repeated failures lead to temporary account locking. This feature reflects practical security practices used in modern web applications.

Research Problem

How can a secure, simple, and user-specific web-based note management system be designed and implemented using Spring Boot and MySQL to improve note organization and access control?

Aim

To develop a secure e-notes web application that enables authenticated users to manage personal notes efficiently.

Objectives

Scope of the Study

The scope of this project is limited to the design, development, and functional analysis of a secure personal note management application. The system supports user registration, login, user-specific note creation, note viewing, note editing, note deletion, and temporary account locking after repeated failed login attempts. The project is intended as a browser-based academic application built with modern Java web technologies.

The study does not include advanced collaboration features such as note sharing, attachments, category tagging, reminders, mobile application support, or an administrative dashboard. It also does not attempt enterprise-scale deployment or performance benchmarking. These boundaries help keep the project focused, realistic, and aligned with the current implementation.

Literature Review

The present project is grounded in the broader field of web application development, database systems, and information security. Previous academic and industry work in this area generally highlights three core ideas: centralized information management, secure user authentication, and persistent data storage.

Studies on information systems emphasize that digital record management improves accessibility, consistency, and retrieval speed. When information is stored in a structured database rather than in isolated files or physical records, users can access it more reliably and maintain it more efficiently. This idea supports the use of relational databases in note management applications.

Research in software engineering also shows that layered architectures improve maintainability and scalability. In this project, the controller-service-repository structure reflects that principle by separating presentation logic, business logic, and persistence logic. Such modular organization helps future enhancement and testing.

Literature on authentication and access control consistently recommends secure password handling and restricted access to user-owned resources. BCrypt hashing is widely used because it provides stronger password protection than plain text or weak encoding methods. Similarly, role-based access and login attempt monitoring are accepted practices for reducing unauthorized access.

Modern web development studies further encourage frameworks that reduce configuration overhead and accelerate enterprise-ready application development. Spring Boot is frequently adopted in academic and professional settings because it supports rapid development, dependency management, and integration with MVC, security, and JPA modules. Thymeleaf is also recognized as a practical server-side templating engine for Java applications that require dynamic page rendering.

Another important theme in the literature is the role of usability in information systems. A system may be technically secure, but if it is difficult to use, users may avoid it or use insecure alternatives. For this reason, simple interfaces and predictable workflows are often treated as part of successful system design. In the present project, the use of Bootstrap and Thymeleaf helps provide a straightforward user journey from registration to login and then to note management.

Research Methodology

Research Design

The study adopts a descriptive and exploratory design. It is descriptive because it explains the design and behavior of the developed application. It is exploratory because it investigates how a secure note-management solution can be implemented using Spring Boot technologies.

Sampling Technique

The project primarily follows a non-probability sampling approach, specifically convenience-based functional validation, where representative use cases such as user registration, login, note creation, note editing, note retrieval, and deletion are considered for evaluation.

Data Collection

The study uses both primary and secondary sources. Primary sources include functional behavior observed from developing and testing the application modules and input-output validation of registration, authentication, and CRUD operations. Secondary sources include Spring Boot documentation, Spring Security concepts, database design references, and general literature on information systems and secure web applications.

Data Preparation

The project data is prepared by classifying the system into modules and recording expected and observed outcomes for key operations such as registration, login, failed login handling, note insertion, note retrieval, note modification, and note deletion.

Data Analysis

The analysis is based on module-wise functional verification and comparison between intended system behavior and observed output. Security features such as password encryption and account lock behavior are also considered during evaluation.

System Analysis and Design Summary

  1. Entity layer: Contains User and Notes entities.
  2. Repository layer: Provides data access through UserRepository and NotesRepository.
  3. Service layer: Handles business logic such as user registration, password encoding, failed-attempt tracking, and account unlocking.
  4. Controller layer: Manages HTTP requests for registration, login, and note operations.
  5. Configuration layer: Defines password encoding, custom authentication handlers, custom user details, and security rules.
  6. Presentation layer: Uses Thymeleaf templates for home, registration, login, add note, view note, and edit note screens.

Features Implemented in the Current Project

  1. User registration with email uniqueness checking
  2. Password encryption with BCrypt
  3. Login using Spring Security
  4. User role assignment as ROLE_USER
  5. Temporary account locking after three failed login attempts
  6. Automatic unlock after lock duration expires
  7. Add note feature
  8. View note list for logged-in user
  9. Edit own note feature
  10. Delete own note feature
  11. CSRF token inclusion in forms
  12. User-specific data access

Results

The developed system successfully demonstrates the core behavior expected from a secure note management application. The registration module supports user enrollment and prevents duplicate email registration. The authentication module secures application access through Spring Security and encrypted password storage. The note management module enables a logged-in user to add, view, edit, and delete notes. Since notes are mapped to individual users, unauthorized cross-user modification is reduced at the application level.

The project also includes a basic defensive security mechanism in the form of failed login tracking. After repeated invalid login attempts, the user account is temporarily locked. This helps show practical application of security logic beyond basic username-password verification.

The results are both theoretical and empirical. Theoretical results are reflected in the successful application of concepts such as layered architecture, authentication, authorization, and object-relational mapping. Empirical results are reflected in the observed functional behavior of the application during module execution.

Interpretation of Findings

The findings indicate that a secure e-notes system can be effectively implemented using Spring Boot with manageable development effort. The project verifies that user authentication, note ownership, and database persistence can be combined into a coherent application. It also highlights the value of integrating security at the design stage rather than treating it as an optional add-on.

The study also reveals that environment configuration remains an important part of deployment. The project depends on database environment variables for successful runtime operation. This shows that modern application development requires both coding skills and deployment awareness.

Project Execution Requirement

To run this project successfully, the required database environment variables must be set before starting the application. The project uses DB_URL, DB_USERNAME, and DB_PASSWORD for MySQL database connectivity. After setting these environment variables, the Spring Boot application can be started, and the project will run properly.

PowerShell commands:

cd E:\Spring_Boot_Learn\enotes_tracker\Enotes_spring_boot_project
$env:DB_URL="jdbc:mysql://localhost:3306/enotes_db"
$env:DB_USERNAME="root"
$env:DB_PASSWORD="YOUR_DB_PASSWORD"
.\mvnw.cmd spring-boot:run
